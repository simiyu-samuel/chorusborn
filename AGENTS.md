# Chorusborn project instructions

- Read `README.md`, `docs/scope.md`, and the relevant specification before changes.
- The owner's instruction is to commit everything we do: commit each completed,
  coherent work increment after appropriate verification. Do not leave completed
  task work uncommitted. Report the commit and working-tree status.
- Commit only this project's intended files. Never commit secrets, private chat
  transcripts, dependency folders, local databases, or generated recordings.
- Do not rewrite existing commits, discard unrelated changes, or push without
  authorization. Local commits are authorized.
- The local fixture, Twitch OAuth/EventSub, durable proposal queue, and bounded Groq
  compiler exist. Real proposals can be reviewed, proved in carrier or paired neutral-opening scenarios,
  and adopted with source attribution. Local two-channel challenges, canonical channel books, shared matches with visible tie initiative, and explicit priority reordering are implemented.
  A real second-broadcaster demonstration, PostgreSQL and full-suite evaluation remain pending. No claims of broad model accuracy or tactic superiority.
  Twitch tokens are memory-only for now; restart requires reconnecting. Keep status honest.
- Keep the ambitious core: Twitch teaching, evidence-backed lessons, deterministic
  branching replay, persistent playbooks, real attribution, and rival matches.
- AI proposes bounded behavior data. It cannot directly publish a playbook,
  execute viewer code, determine match outcomes, or control the simulation clock.
- The server owns simulation state. Renderers do not determine outcomes.
- Pin active playbooks for a match; adoption and rollback apply at round boundaries.
- Attribute only actual execution records. Rule activation is not proof that a
  viewer caused a win or that a tactic generalizes.
- Before integrations, read current official docs and the relevant installed skills.
  Never invent API scopes, SDK signatures, model IDs, or verified benchmarks.
- Verify semantic properties that matter: replay determinism, policy validation,
  authorization, event deduplication, and disconnected-state behavior.
- Follow `CONTRIBUTING.md`; keep source and supporting documentation in sync.
